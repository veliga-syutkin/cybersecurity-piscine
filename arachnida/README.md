# Arachnida

42 Cybersecurity Piscine — introduction to web scraping and metadata.

- **spider**: downloads the images of a website, optionally recursively.
- **scorpion**: displays the metadata (filesystem, Exif…) of image files.

## Requirements

- Python ≥ 3.10 with the `venv` module
- Dependency: `requests` (installed automatically by `make` into `.venv/`)

## Layout

```
arachnida/
├── Makefile
├── requirements.txt
├── Exif.md          # notes on how Exif is stored in a JPEG
├── common/          # code shared by both programs (e.g. supported extensions)
├── spider_src/      # spider sources (entry point: launcher_spider.py)
├── scorpion_src/    # scorpion sources (entry point: launcher_scorpion.py)
├── spider           # launcher, generated by make
└── scorpion         # launcher, generated by make
```

## Build

```sh
make        # creates .venv/, installs requirements.txt, generates ./spider and ./scorpion
make clean  # removes every __pycache__/ and data/
make fclean # also removes .venv/ and the launchers
make re     # fclean + all
```

## Usage

### spider

```sh
./spider [-rlp] [--delay SECONDS] URL
```

| Option | Description | Default |
|---|---|---|
| `-r` | recursively downloads the images | — |
| `-r -l N` | maximum recursion depth | `5` |
| `-p PATH` | destination directory | `./data/` |
| `--delay SECONDS` | delay between two pages (integer ≥ 0; `0` disables it) — extra option, not in the subject | `1` |

Downloaded extensions: `.jpg` / `.jpeg`, `.png`, `.gif`, `.bmp`.

### scorpion

```sh
./scorpion FILE1 [FILE2 ...]
```

Supported formats: the same as spider.

## Design choices

<!-- To fill in: these are the questions an evaluator will ask. -->

### spider

- **Depth**: the start page is level `0`; pages linked from it are level `1`, and so on.
  `-l 0` means no descent: only the start page is processed. A negative value is
  an error: the program exits before doing anything.
- **`-l` without `-r`**: the user is explicitly warned that `-r` is missing, and the
  program runs as if `-r` had been given along with `-l`.
- **URL scheme**: only `http` and `https` are accepted; any other scheme
  (`file://`, `ftp://`…) is rejected, so a URL can never make spider read local
  files. A URL without a scheme gets `https://`. An `http` URL is accepted with a
  warning: the connection is unencrypted, so content can be read or altered in
  transit.
- **Crawl scope**: same host only — safer, simpler, and predictable.
  - `www.site.com` and `site.com` are treated as the same host;
  - `http` and `https` are treated as equivalent;
  - subdomains are **out of scope**: a crawl started on `site.com` does not visit
    `blog.site.com`, and the other way round. Including them was considered and
    rejected: on large sites the crawl explodes (`wikipedia.org` has 300+ language
    subdomains), and a proper "same site" check (`site.co.uk`, `alice.github.io`)
    would need the Public Suffix List;
  - **the scope follows the start page's redirects, once**: if `site.com`
    redirects to `fr.site.com`, the scope becomes `fr.site.com` (the host the
    site really lives on), otherwise the start page itself would be rejected.
    Later redirects to another host are skipped with a warning;
  - the scope applies to **pages** (what is crawled), not to **images**: an image
    shown on an in-scope page is downloaded whatever its domain (e.g. a CDN on
    another domain). An image is a single request, never followed further.
- **URL normalization** — every URL is turned into a canonical form, used as the key
  for "already seen" checks:
  - resolved to an absolute URL against the page's final URL (after redirects);
  - scheme and host lowercased (the path keeps its case);
  - default ports (`:80`, `:443`) removed;
  - fragment (`#…`) removed;
  - empty path replaced by `/`, `.` and `..` segments resolved;
  - `www.` prefix and `http`/`https` difference ignored (see scope);
  - `/dir` and `/dir/` are kept distinct;
  - the query string is kept (`?page=2` is a different page).
- **Extracted URLs** — principle: *what the user sees, spider downloads*:
  - images: `<img src>`, `<img srcset>`, `<source srcset>` (inside `<picture>`);
    every candidate of a `srcset` is downloaded (several sizes of a same image
    are distinct URLs);
  - links (pages to crawl): `<a href>`, `<area href>`, `<iframe src>`,
    `<frame src>`, and the `<meta refresh>` target (see below);
  - **image links**: a link whose path has a supported image extension
    (`<a href="big.jpg">`, e.g. a thumbnail gallery) is handled as an **image of
    the page**, not as a page: same rules as `<img>` (no scope, "already seen",
    signature check), downloaded whatever the depth and even without `-r`;
    an image already downloaded through `<img>` costs no extra request;
  - not extracted: lazy-loading attributes (`data-src`…, non-standard), CSS
    images (`background-image`), and anything added by JavaScript — spider reads
    the HTML as served, it does not run scripts.
- **`<base href>`**: when a page declares a base URL, relative links are resolved
  against it instead of the page URL. Only the first `<base>` with an `href`
  counts, and it is itself resolved against the page URL.
- **`<meta http-equiv="refresh">`**: not handled as a redirect; its target URL is
  treated as an ordinary link found on the page (followed with `-r`, one level
  deeper, same scope and "already seen" rules).
- **`robots.txt` / `nofollow`**: ignored on purpose. The subject does not require
  it, and `robots.txt` is a convention (RFC 9309), not an access control.
  Politeness is kept through a delay between requests and an honest User-Agent.
  Every URL goes through a single "may this URL be fetched?" check (scope +
  already seen), where `robots.txt` support could be added later.
- **HTTP 429 (Too Many Requests)**: the crawl stops immediately with
  `Received 429 - Too Many Requests; you may retry later, recommended time: <Retry-After>`.
  `Retry-After` is not retried automatically: servers often over-estimate it.
  - `Retry-After` is always shown as an absolute date and time (a value in
    seconds is converted to "now + seconds"); when the header is missing, the
    message ends without a recommended time.
  - Files already downloaded are kept; the exit code is `1`.
- **Delay between requests**: 1 second between **pages** by default, no delay
  between the images of a same page (like a browser loading a page).
  `--delay SECONDS` changes it: long form only (kept apart from the subject's
  `-rlp`), integer `≥ 0`, `0` disables the delay.
- **Visited pages / images**:
  - a page is marked as seen when it is queued, not when it is fetched;
  - after a redirect, the final URL is marked as seen too;
  - image URLs are normalized the same way, so an image is downloaded only once.
- **User-Agent**: a custom, honest one (`arachnida-spider/1.0`) — neither the
  library default nor a browser imitation.
- **Image validation**: an image URL is selected by its extension, then the
  response must have a `2xx` status, and the downloaded content must start with
  the signature (magic bytes) of a supported format — the signatures shared with
  scorpion in `common/`. This rejects error pages and "soft 404s" (an HTML page
  served with `200` behind a `.png` URL), while accepting real images served with
  a wrong `Content-Type`. A `Content-Type` of `text/html` is used as an early
  filter, before downloading the body.
- **Extension correction**: when the real format (detected from the content's
  signature) does not match the URL's extension — e.g. PNG data behind
  `photo.jpg` — the file is saved with the extension of its real format
  (`photo.png`). Collision rules then apply to the corrected name.
- **Images with no name** (URL path such as `/images/.png`): they are not missed
  — `.png` is read as the extension, although Unix would see a hidden file with
  no extension. They are saved as `hidden_imageX.ext`, `X` being the first free
  number (`hidden_image1.png`, `hidden_image2.png`, …); identical content is not
  saved twice.
- **File name collisions**: if a file with the same name already exists, both are
  compared byte for byte:
  - identical → the new file is not saved;
  - different → it is saved as `name_1.ext` (then `name_2.ext`, …).
- **Timeout**: 10 seconds to connect, and 10 seconds for each read.
- **Redirects**: followed by the HTTP library; the final URL is the base for
  relative links. A page redirected out of scope is skipped with a warning; a
  page redirected to an already crawled one is not processed twice.
- **Page encoding**: the charset of the `Content-Type` header if any, otherwise
  UTF-8 (instead of the old HTTP default, ISO-8859-1).
- **File names**: taken from the URL path, percent-decoded
  (`my%20image.png` → `my image.png`); `/`, `\` and NUL are replaced by `_` so
  that a name can never escape the destination directory (path traversal, e.g.
  `a%2F..%2Fevil.png` → `a_.._evil.png`); names are limited to 200 bytes.
  Saved files get the usual permissions (`666` minus the user's umask).
- **Output**: one line per page (`[depth N] url`), `+ file` for a saved image,
  `= url` for a duplicate; warnings and errors on stderr; a summary at the end
  (pages, saved, duplicates, rejected, errors).
- **Exit codes**: `0` when the start page was crawled, even if some other pages
  or images failed (broken links are normal on the web); `1` when the start page
  fails (HTTP error, unreachable, not an HTML page — a start URL pointing
  directly to an image is not downloaded) or on HTTP 429; `2` on invalid
  arguments; `130` on Ctrl-C.

### scorpion

- **Format detection** — signature (magic bytes) vs extension:

  | Known signature | Supported extension | Behavior |
  |---|---|---|
  | yes | yes, matching | processed |
  | yes | yes, mismatched (e.g. PNG data in `photo.jpg`) | processed according to the signature, with a warning |
  | no | yes | error: content is not a valid image of that type (e.g. "content is not a valid JPEG") |
  | yes | no | processed |
  | no | no | skipped, with a "not supported" notice |

- **"Creation date"**: both dates are shown, each under its exact name;
  `DateTimeOriginal` takes priority when present.
  - **Filesystem birth time**: `null` when the system does not provide it.
    Python 3.12 does not expose it on Linux, so it is read with the `statx()`
    system call (through `ctypes`, standard library); on macOS Python provides
    it directly.
  - **Exif `DateTimeOriginal`**: the **camera's clock** at capture time — no
    time zone, and only as accurate as the device's settings.
- **Filesystem attributes** ("basic attributes"): size; permissions (readable
  `-rw-r--r--` and octal `644`); owner and group (name and number); four dates —
  `birth` (creation), `modified` (content changed), `changed` (inode metadata
  changed — **not** the creation), `accessed` (last access).
- **Output format: JSON**, pretty-printed, on stdout:
  - the whole output is **one valid JSON document**: an array with one object
    per file, in the order of the arguments;
  - a missing value (birth time not provided, absent tag) is `null`;
  - a file that cannot be processed (not found, unreadable, not supported,
    corrupted) gets an entry `{"file": ..., "error": "..."}` in the array, and a
    message on stderr for the human reader.
- **Exif tags**: **all** the tags found are shown — nothing is hidden, since the
  point of the project is to reveal what metadata leaks. Known tags (names from
  the Exif specification) are shown by name, unknown ones as `"Tag 0xA431"`
  with their raw value.
- **Converted values**: a converted value is an object holding the **raw** value
  (as stored, per the specification) **and** its readable form; simple values
  (text, single number) stay as they are:
  - GPS coordinates: degrees / minutes / seconds text **and** decimal degrees,
    with N/S/E/W;
  - enumerations as text (Orientation `1` → `"top-left"`, ResolutionUnit…);
  - rationals made readable (ExposureTime `1/100 s`, FNumber `f/1.8`…);
  - long binary values (MakerNote, raw bytes): size and first bytes in
    hexadecimal instead of the whole content;
  - **encoded texts** — UserComment, GPSProcessingMethod, GPSAreaInformation
    start with an 8-byte character code [Exif §4.6.5]: the text is decoded
    accordingly (ASCII; Unicode as UTF-16 in the file's byte order; JIS X 0208;
    "Undefined" tried as UTF-8) and shown with its encoding and the raw bytes;
    if it does not decode to readable text, the hexadecimal form is kept.
- **Long texts** (PNG text chunks, JPEG comments, GIF comments, Exif ASCII
  tags): beyond 1000 characters, shown as
  `{"length": n, "head": <first 1000 characters>, "truncated": true}`.
  Compressed texts (PNG `zTXt`, compressed `iTXt`) are never decompressed beyond
  1 MiB — protection against "zip bombs" (a few KB that expand to gigabytes);
  `"decompression_limit_reached": true` then tells the real text is longer.
- **XMP** (Adobe's XML metadata — often the richest leak: GPS, author, editing
  history, document IDs): the packet is shown **as text, never parsed** —
  parsing untrusted XML exposes to XXE and entity-expansion attacks, and the
  standard `xml` modules are not designed for hostile input. Found in a JPEG
  APP1 segment, a PNG `iTXt` chunk (keyword `XML:com.adobe.xmp`) or a GIF
  application extension (`XMP DataXMP`). It is shown up to 64 KiB — the size
  of a whole JPEG segment, i.e. in practice all of it — instead of the
  1000-character limit of other texts.
- **Warnings** are kept where they come from: file-level problems in the
  file's `"warnings"` (extension mismatch, truncated segment, bad CRC…), Exif
  problems in `"exif": {"warnings": …}` (IFD loop, offset out of bounds,
  unknown type…).
- **Exit codes**: `0` when every file could be read (a file with no metadata is
  not a failure); `1` when at least one file failed — the others are still
  processed; `2` on invalid arguments; `130` on Ctrl-C.

## AI usage

This project was built with the help of an AI assistant (Claude, by Anthropic,
used through Claude Code). How it was used, and who did what:

**Done by the AI**

  specifications it cites (Exif 2.31, TIFF 6.0, ITU-T T.81, PNG, GIF89a, BMP).

  [Design choices](#design-choices): `Makefile`, `common/formats.py`,
  `spider_src/launcher_spider.py`, `spider_src/urls.py`,
  `spider_src/html_links.py`, `spider_src/crawler.py`, and all of
  `scorpion_src/` (`launcher_scorpion.py`, `fileinfo.py`, `jpeg.py`, `png.py`,
  `gif.py`, `bmp.py`, `exif.py`, `exif_tags.py` — tag names and enumerations
  extracted from the Exif 2.31 specification).
- Wrote throwaway tests to check each module, and explained each module after
  writing it.

**Done by the author**

- Every design and behavior decision: all the entries of
  [Design choices](#design-choices) were chosen by the author, from options
  presented with their trade-offs.
- Project layout, review and validation of the code and documents.

**How it is kept honest**

- Every technical statement in `Exif.md` points to a section of a specification.
- Every behavior of the code maps to an entry of *Design choices*.
- The author must be able to explain any line of the project; this section is
  updated whenever the split of the work changes.
